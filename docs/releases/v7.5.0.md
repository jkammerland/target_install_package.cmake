# target_install_package v7.5.0

This release adds CMake 4.5 support for stable SBOM generation and CPS executable and module components, and documents multiple-component installs. It also keeps the wrapper's argument parsing from changing CMP0174 in calling projects.

## Highlights

- Generates [SPDX SBOMs](../sbom.md) with the stable CMake 4.5 `install(SBOM)` command, without an activation value. The new `SBOM_DEFAULT_LICENSE` option sets the declared license of exported targets that have no `SPDX_LICENSE` property.
- Exports executables and `MODULE` libraries as [CPS](../cps.md) `executable` and `module` components when the producer uses CMake 4.5. They are not default components, so consumers request them with `find_package(<package> COMPONENTS ...)`.
- Documents [multiple-component installs](../multi-component-install.md) with `cmake --install --component`, including the CMake 4.4 releases that can report success after a component fails.
- Keeps CMP0174 private to argument parsing in `target_install_package()` and `export_cpack()`. Calling directories, subdirectories added later, and functions defined later keep the caller's policy setting, and empty `export_cpack()` signing options no longer produce CMP0174 warnings.

## Compatibility

- The core package-install path remains compatible with CMake 3.25.
- SBOM generation requires CMake 4.3 or newer. CMake 4.3 and 4.4 still require `CMAKE_EXPERIMENTAL_GENERATE_SBOM` set to the activation value for that version. CMake 4.5 writes one `<SBOM_NAME>-<config>.spdx.json` document per installed configuration, and `SBOM_DEFAULT_LICENSE` requires CMake 4.5.
- CMake 4.5 writes CPS 0.15.0, which requires CMake 4.5 consumers. CMake 4.3 and 4.4 consumers fall back to the CMake config package installed alongside it. CMake 4.3 and 4.4 producers still reject executables and `MODULE` libraries for CPS exports.
- Multiple names after `--component` require CMake 4.4. CMake 4.4.0 through 4.4.5 can mask a component failure ([CMake issue 27906](https://gitlab.kitware.com/cmake/cmake/-/issues/27906)); CMake 4.5.0 stops at the first failing component and returns a failure. On CMake 4.4, install components with separate serial invocations.
- In projects whose minimum version is below CMake 3.31, code after the first `target_install_package()` call now sees the project's own CMP0174 setting. Set the policy explicitly if that code relies on `NEW`.

Release CI exercises the CMake 3.25 core floor, the CMake 3.28, 4.2, 4.3, and 4.4 feature boundaries, and CMake 4.5.0. Exact CMake versions come from SHA-256-pinned Kitware release archives where one is listed for the runner platform.
