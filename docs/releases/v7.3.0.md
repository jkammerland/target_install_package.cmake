# target_install_package v7.3.0

This release expands native packaging controls and release diagnostics with AppImage output, configurable compression, deterministic archive ownership, and SARIF reporting.

## Highlights

- Adds explicit Linux AppImage packaging with prerequisite and metadata validation, plus an end-to-end artifact example.
- Adds generic, archive-specific, and Debian-specific CPack compression levels with generator-aware validation and documented override precedence.
- Adds deterministic archive UID and GID controls for tar and ZIP packages, with warnings when selected generators may ignore them.
- Adds CMake 4.4.2 configure diagnostics as SARIF, retaining failed diagnostics as workflow artifacts.

## Compatibility

- The core package-install path remains compatible with CMake 3.25.
- AppImage packaging requires Linux, CMake 4.2 or newer, `appimagetool`, `patchelf`, installed desktop metadata and icons, and explicitly installed runtime dependencies.
- Compression levels and deterministic archive ownership require CMake 4.3 or newer.
- AppImage output is monolithic and does not provide a byte-for-byte reproducibility guarantee.
- Archive ownership is stored by tar and ZIP; other generators may ignore it.
- SARIF reporting is confined to the CMake 4.4.2 CI diagnostics lane.

Release CI continues to exercise the CMake 3.25 core floor and the independently gated CMake 3.28, 4.2, 4.3, and 4.4 feature boundaries.
