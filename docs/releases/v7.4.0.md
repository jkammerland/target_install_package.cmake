# target_install_package v7.4.0

This release adds reusable installed-consumer checks and improves package registration, CPack metadata, and source-to-installed usage guidance.

## Highlights

- Adds an [installed and relocated consumer check](../installed-consumer-check.md) that builds a real consumer against a fresh installation, moves the installation, and repeats with a separate build. It supports multi-configuration generators, cross-compilation, emulators, and retained failure logs.
- Preserves calling-directory paths, per-target install destinations, custom template substitutions, and Debug postfixes during deferred export registration. Automatic RPATH follows registered shared-library installation directories.
- Supports a literal `export_cpack()` call and preserves metadata containing quotes, semicolons, backslashes, or explicit empty values. Repeated list arguments accumulate, and missing required values receive configuration diagnostics.
- Provides portable archive defaults, an explicit `ARCHIVE_FORMAT` selector, native-generator prerequisite diagnostics, and warnings about omitted manual install components.
- Adds [API references](../../README.md#shipped-functions-and-files) and matching source/installed consumer examples with unconditional aliases, optional embedded installation, and explicit static-library dependency metadata.

## Requirements and defaults

- Core helpers and the installed-consumer check require CMake 3.25 or newer. Existing optional features retain their documented CMake requirements.
- Default CPack output is `TGZ` on Linux/macOS and `ZIP` on Windows. Native package formats are selected explicitly.
- Debug postfix precedence is an explicit wrapper value, including an empty string, then the target property, then `d` when unset.
- The consumer check runs native tests by default. Cross-compiled consumers are configured and built; runtime tests require an emulator or an explicit runtime request. An enabled runtime check rejects an empty test suite.
